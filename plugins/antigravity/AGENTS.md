# antigravity

Setup, use and privacy: read [README.md](README.md). The job machinery is a copy of the codex plugin's, adapted (images come from agy's artifacts folder, no answer recovery from agy's files); a fix to one usually belongs in both.

- `hooks/register.tsx`: the literal `$.tool.register`/`$.command.register` calls in `session.start`, the `tool.call` and `command.run` hooks, the `prompt.compose` section, the model check against `agy models` (`checkedModel`), and the host access each run gets (`depsOf`). Pure modules take that access injected (`tests/register.test.ts`: `session start registers the ask, image, review and jobs tools and the four commands`, `a model agy models does not list is refused with the valid ids before anything runs, and bad inputs are answered`, `/agy-ask checks the defaultModel against agy models like the tools do`, `the system prompt tells Claude to reach for ask on its own and for review before a PR`).
- `args.ts`: the agy argv. Print mode with `--output-format=stream-json`, `--disable-slash-commands`, `--sandbox` and `--print-timeout` 30 s short of the background limit, so agy ends on its own first; never `--dangerously-skip-permissions` (reads pass without it, measured on agy 1.5.3) nor `--mode plan` (ignored under `--disable-slash-commands`). Every value is fused to its flag. Every prompt ends with `NO_EDIT`; a review's is `reviewPrompt` (P0 to P3, `path:line`, "No findings." allowed, the optional focus). An image's prompt names its reference and ends with `IMAGE_CLOSE` instead (generate with the `image-generator` subagent, write nothing yourself), and the reference's folder outside the work folder gets `--add-dir` (`tests/register.test.ts`: `an ask runs agy sandboxed in the session folder, never skipping permissions, saves the answer and returns it`, `an image runs agy sandboxed in an empty work folder of the plugin’s, never skipping permissions, and copies the image it added to its artifacts folder, with a preview`, `an image follow-up edits from a reference and saves only the images it added, numbered beside its out`).
- `events.ts`: reads a run's end. `readRun` takes the `result` line, stderr's `AGY_ERROR` line and the exit status into the closed `Reason` set (`quota exhausted` from `RESOURCE_EXHAUSTED`, `timed out` from `print_timeout`, `interrupted`, `local error` for exit 1, `agy error`); `short_error` is never shown and `redact` blanks project and region names. `conversationOf`/`modelOf` read the `init` line by pattern, since it lists every tool and can pass the bytes read (`tests/register.test.ts`: `a failed run says why in the closed set of reasons, and never shows the Google Cloud project or region`).
- `workspace.ts`: the git side. Its git runs with `core.fsmonitor` off and its diff without external diff or textconv, since the host turns off only repo hooks. `FINGERPRINT` is one hash of `git status` and of the content of each modified or untracked file that still exists (`git hash-object` without `-w`), so an ask's edits show, deletions and a second edit to a changed file included, while nothing is written to the repository and the job stays small in the store; `review` checks the range has files, adds a detached worktree under `$TMPDIR/agy/worktrees/<id>` and writes the diff there through a shell redirect (`WRITE_DIFF`, since a large diff could pass the host's output limit); `remove` falls back to `rm -rf` and prunes; `image` makes an image run's empty work folder under `$TMPDIR/agy/.work/<id>`, which `discard` deletes (`tests/register.test.ts`: `an ask in a git repository notes nothing when the working tree stayed the same, and warns when it changed`, `a review without a target covers the branch against origin/HEAD in a throwaway worktree holding the diff, then removes it`, `a review that finds its worktree edited says so; one with nothing to diff starts no run`).
- `runner.ts`: `createRunner` keeps every run as a `Job` in `$.store` (`job:<id>`) with its workspace, and its agy process detached (`RunFiles`), as codex does: foreground wait, background limit, one watcher per job named by a token, heartbeats, takeover of a job unwatched for a minute, a pid stopped only when `ps` shows it is still that agy run. A follow-up on a conversation with a running or starting job is refused (two turns at once hang agy). A job is saved before its workspace is made, so a sweep never takes a worktree being built, and a failure on the way removes the job, its folder and its worktree; its deadlines count from just before the launch. An image job keeps the image names its Conversation's artifacts folder held before the run (`before`). `finish` checks the workspace, removes a review's worktree or an image's work folder and saves the answer, or the images (`saveImages`); a run gone without an exit status is `lost`, never re-run. `resume` prunes finished jobs past 7 days or the newest 50 and removes worktrees no running job holds (`tests/runner.test.ts`: `past the foreground wait a review goes on as a job, whose end sends a notice without the answer and removes its worktree`, `a job past the background limit is stopped once its process is checked, and reported as timed out`, `a run whose process vanished without an exit status is lost, and never run again`, `a follow-up on a conversation that is still running is refused, naming its job`, `two follow-ups started at once on one conversation: one runs, the other is refused`, `a review worktree being made is already held by its job, so a session start meanwhile leaves it alone`, `after a reload the session picks its running job up again, with one watcher and one notice`, `another session’s job no watcher has seen for a minute is taken over and notified here; a fresh one is left alone`, `session start prunes finished jobs past 7 days or the 50 newest, and removes worktrees no running job holds`, `past the foreground wait an image goes on as a job, whose end copies the image its run added, names it in the notice and removes the work folder`).
- `detached.ts`: `ROOT_CHECK` makes the plugin's folder private (mode 700, owned by the user, not a symlink) before each run, or the run is refused; without `TMPDIR` the folder is `/tmp/agy-<uid>` (`tests/register.test.ts`: `without TMPDIR the plugin works under a folder of the user’s own, made private before a run`, `a plugin folder the user does not own alone stops the run before agy starts`). `LAUNCH` starts agy under `umask 077` with stdin from `/dev/null` (`agy -p` waits on an open stdin) into `$TMPDIR/agy/runs/<id>/` (`events.jsonl`, `stderr.txt`, `pid`, `exit`); a read takes the first 8 KiB and the last lines of the events, never the whole file. `isAgyRun` matches the `ps` command by its stream-json flag.
- `review.ts`: `resolveReview` (outside a repository it refuses, no target becomes `--base` of origin/HEAD, else `main` or `master`, else it asks for a base; the untracked files left out become `Request.note`) and `/agy-review` arguments (`reviewCommandInput`: an optional target flag, then the focus) (`tests/register.test.ts`: `a review outside a git repository is refused before agy runs`, `without origin/HEAD the review falls back to main, else master, else asks for a base`, `/agy-review takes one target and a focus, says it was a review, and refuses what it cannot read`).
- `doctor.ts`: `/agy-doctor`, spending no quota: `--version` against 1.5, `agy models` as the sign-in check, `-p=/usage` without `--disable-slash-commands` (with it, the probe would be a real prompt), and whether the artifacts folder exists (`tests/register.test.ts`: `/agy-doctor reports the executable, version, sign-in, models, quota and image artifacts folder, spending none`).
- `input.ts`: tool input to `Request` (conversation id, model and effort shapes, absolute paths without `.` or `..` parts, an image's reference by its extension, one review target at most, the `defaultModel` option); `placementError` refuses a file outside the project whose folder is the home folder or above (its `--add-dir` would open it all) and an `out` outside the project and the answers folder or inside `.git` (by the path as written: a symlink inside the project is followed) (`tests/register.test.ts`: `an ask refuses a file whose folder would open the home folder or above, and an out outside the project and the answers folder`, `an image run that added no image says so with agy’s text, and bad image inputs are refused before agy runs`). `locate.ts`: `agyPath`, else PATH, else `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`. `output.ts`: the saved Markdown, conversation, model and target first; `saveImages` copies the images an image run added to `~/.gemini/antigravity-cli/brain/<conversation>/` (agy's stream does not name them), oldest first, numbered beside `out` when there are several, with `sips` previews on macOS and a Markdown record (`tests/register.test.ts`: `/agy-image takes a prompt, shows where the images are, and tells Claude they are AI-generated`). `presentation.ts`: every text the model or the person reads; `prompts.ts`: tool descriptions and the system prompt section; `tool-schemas.ts`: input schemas and command texts.
- `hooks/schema.ts`: the shared `SchemaFor` and `allOf`, a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; each `inputSchema` satisfies `SchemaFor` of its `McpToolInputs` entry in `types/index.d.ts`. A new tool: its schema in `tool-schemas.ts`, its `McpToolInputs` entry, its literal registration and `tool.call` hook in `register.tsx`, and the names in `tests/register.test.ts`.
- Tests: `tests/host.ts` (the host fake: scripted agy runs, git keyed by arguments with a review worktree written `<wt>`, fingerprints in turn, folder listings with file entries for the artifacts folder) and `tests/fakes.ts` (agy's stream-json lines and `AGY_ERROR`) for `tests/register.test.ts`; `tests/runs.ts` (detached runs, `$.store` and workspaces in memory) for `tests/runner.test.ts`.
- Checks: [root commands](../../AGENTS.md#commands). A live check: `/agy-doctor`, then one `/agy-ask`, one `/agy-image` and one `/agy-review` on a small branch (all spend agy quota).
