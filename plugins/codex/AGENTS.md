# codex

Setup, use and privacy: read [README.md](README.md).

- `hooks/register.tsx`: the literal `$.tool.register`/`$.command.register` calls in `session.start` (the engine's scan needs the names), the `tool.call` and `command.run` hooks, the `prompt.compose` section, and the host access each run gets (`depsOf`: `$.process.spawn` for the Codex child, `$.process.run` for `sleep`, `mkdir`, `cp` and `sips`, the files, `TMPDIR`, `HOME`, `CODEX_HOME` and `PATH`). Pure modules take that access injected.
- `args.ts`: the `codex exec` argv. Every run is locked read-only and never asks for approval (`-c sandbox_mode="read-only"`, `-c approval_policy="never"`, whatever the user's `config.toml` says; `exec resume` takes no `--sandbox`), an ask searches the web (`web_search="live"`) and an image run does not; a new thread gets `--thread-source` and, for an image, `-C` the plugin's empty folder; `--` ends the options because `--image` takes several values (`tests/args.test.ts`: `a new ask runs read-only, never asks for approval, searches the web and records its source`, `a follow-up resumes its thread, keeps the read-only lock and takes no folder or source`).
- `events.ts`: reads the `--json` lines (`thread.started`, the last `agent_message`, `turn.failed`, `error`); an `error` event before an answer (a reconnect) does not fail a run that answers (`tests/events.test.ts`: `an error event before an answer does not fail a run that answers`).
- `runner.ts`: `createRunner` keeps every run as a `Job` in `$.store` (`job:<id>`, the id unique across sessions; the request without images or files, the prompt cut to 200 characters) and its Codex process detached (`RunFiles`), so jobs outlive a plugin reload and the session. The foreground wait (`foregroundMinutes`) and a background job (up to `backgroundMinutes` from its start, which also cuts the foreground wait short) read the run's folder every 2 s through `sleep` host processes, since a hook's clock stops only while a host call is in flight; every fifth read checks the process is still there, and a run found gone is read once more before it counts as lost. A run that ends in the foreground leaves no job; one whose wait fails goes on as a job and is never stopped for it. A job has one watcher, named by a token in its record: a watcher whose token was replaced lets go (the old module's after a reload), and every tenth read is a heartbeat (`seenAt`). Past the limit a job is stopped only once `ps` shows its pid is still that Codex run; a run that vanished without an exit status gets its answer from Codex's session files when one is stamped after the run's start, else it is `lost`, and never re-run. A job's end sends a toast and a `prompt.submit` notice with paths and the thread, never the answer. `resume`, at `session.start`, prunes finished jobs past 7 days or the newest 50, then watches the running jobs of the session's project that are its own (the id survives a reload) or that no watcher has seen for a minute (their session ended or changed id); the jobs tool lists that project's jobs (`tests/runner.test.ts`: `past the foreground wait the run goes on as a job, whose end sends a notice without the answer`, `a job past the background limit is stopped once its process is checked, and reported as timed out`, `a run whose process vanished without an answer is recovered from Codex’s own files, else lost`, `after a reload the session picks its running jobs up again and sends their end notice`, `a job has one watcher: the one a reload left behind lets go, and one notice goes out`, `another session’s job no watcher has seen for a minute is taken over, finished and notified once`, `a foreground wait that fails leaves the run going as a job for the next session start`, `finished jobs are pruned past 7 days or past the 50 newest, with their run folders`).
- `detached.ts`: `detachedRuns`, the `RunFiles` on this machine. `ROOT_CHECK` makes the plugin's folder private (mode 700, owned by the user, not a symlink) before each run, or the run is refused; without `TMPDIR` the folder is `/tmp/codex-<uid>` (`tests/register.test.ts`: `without TMPDIR the plugin works under a folder of the user’s own, made private before a run`, `a plugin folder the user does not own alone stops the run before Codex starts`). `LAUNCH` starts Codex under `umask 077` and `nohup` with every stream redirected (else `$.process.run` waits out its timeout) into `$TMPDIR/codex/runs/<id>/` (`events.jsonl`, `stderr.txt`, `pid`, `exit` with the status and the time, and `answer.md`, which `-o` writes), the arguments passed as positional parameters; a `$.process.spawn` child would die with the module on a reload. A read takes only the ends of the events (`head`/`tail -c`), never the whole file, and the answer from `answer.md`. `recover` finds the thread's rollout under `$CODEX_HOME/sessions` or `archived_sessions` (`.zst` through `zstd`) and reads its newest `task_complete`, only when stamped after the run's start (`tests/detached.test.ts`: `only a Codex exec process counts as the run, so a reused pid is never killed`, `a rollout gives its newest task_complete answer only when it is from this run, never an earlier turn`; `tests/register.test.ts`: `session start picks up a job a reload left running, and its end notice arrives in this session`, `another session’s job whose process is gone gets its answer back from Codex’s session files`).
- `output.ts`: answers go to `$TMPDIR/codex/` as Markdown with the thread first; images are copied from `$CODEX_HOME/generated_images/<thread id>/`, where Codex saves them (its `--json` stream does not name them): the names there before a follow-up are left out, the rest go out oldest first (`tests/output.test.ts`: `the images a run added are copied out oldest first, numbered when there are several, with previews`).
- `review.ts`: a review's target and repository checks (`resolveReview`: outside a repository it refuses, no target becomes `--base` of origin/HEAD, else `main` or `master`, else it asks for a base; a base review notes the untracked files it leaves out, counted with `git ls-files --others --exclude-standard`; git that cannot run is an answer, not a throw, as `Request.note`, which `saveAnswer` puts before the answer), and `/codex-review` arguments (`reviewCommandInput`); `args.ts` turns the target into `codex exec review` flags, read-only and without web search, with no `-C` since `exec review` takes none (`tests/args.test.ts`: `a review against a base runs read-only, without web search, records its source and names the base`; `tests/register.test.ts`: `a review outside a git repository is refused before Codex runs`, `a review without a target covers the branch against origin/HEAD and says which untracked files it left out`).
- `input.ts`: tool input to `Request` (thread id, model and effort shapes that cannot break the TOML value, absolute paths, an `out` without `.` or `..` parts; images among `files` become `--image`, the rest are listed in the prompt for Codex to read); `placementError` keeps `out` inside the project or the answers folder and outside `.git` (by the path as written: a symlink inside the project is followed) (`tests/register.test.ts`: `an answer or image is saved only inside the project or the answers folder, never in .git or through . or ..`). `locate.ts`: `codexPath`, else PATH, else `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`. `doctor.ts`: `/codex-doctor`. `presentation.ts`: every text the model or the person reads; `prompts.ts`: tool descriptions and the system prompt section; `tool-schemas.ts`: input schemas and command texts.
- `hooks/schema.ts`: the shared `SchemaFor` and `allOf`, a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; each `inputSchema` satisfies `SchemaFor` of its `McpToolInputs` entry in `types/index.d.ts`. A new tool: its schema in `tool-schemas.ts`, its `McpToolInputs` entry, its literal registration and `tool.call` hook in `register.tsx`, and the names in `tests/register.test.ts` (`session start registers the ask, image, review and jobs tools and the four commands`).
- Tests: `tests/fakes.ts` (Codex's JSONL output and memory output deps) and `tests/runs.ts` (detached runs and `$.store` in memory) for the pure modules, `tests/host.ts` (the host fake, including a `process.spawn` generator) for `tests/register.test.ts`.
- Checks: [root commands](../../AGENTS.md#commands). A live check: `/codex-doctor`, then `/codex-ask` and `/codex-image` (the last spends OpenAI usage); on a Mac, `/codex-cu on` and one `mcp__codex__computer_use` call.

## Computer use (macOS)

Setup, use, privacy or live desktop checks: read the README's [Computer use](README.md#computer-use-macos). MCP app-approval elicitation belongs to the helper; the plugin cannot answer it.

- `hooks/computer-use/register.tsx` (`registerComputerUse`): the computer use hooks other than `session.start` and `prompt.compose`, which the plugin can hold only once each and which live in `hooks/register.tsx`: there `session.start` registers `computer_use` and `/codex-cu` only when `uname -s` prints `Darwin` (`routing.ts` `UNAME`, `isMac`; a failing `uname` means no), and `prompt.compose` adds the `codex:computer-use` section only while the switch is on. The switch is `$.store` key `computer-use:enabled` (`routing.ts` `ENABLED`, `isOn`): off until `/codex-cu on`, then held across sessions (`tests/register.test.ts`: `on macOS session start also registers the computer use tool and /codex-cu`, `elsewhere, or when uname cannot run, computer use is not registered`, `computer use starts off: no prompt section and Claude’s own desktop tools run until /codex-cu on`). `known.ts` holds what the module last learned (the platform from session.start, the switch at every read and write): off macOS the guard, the band and the session-end release stand aside, and the guard's `.catch` lets the own tool run when the switch was last seen off and refuses with `UNCHECKED_OWN` when it was never read (`tests/register.test.ts`: `off macOS the computer use hooks stand aside: Claude’s own desktop tools run even with the switch stored on`; `tests/computer-use/session-end.test.ts`: `the guard catch lets the own desktop tool run off macOS or with the switch last seen off, and cannot vouch for a switch never read`). The band draws a question only while its call still waits on it, so one a reload left in `$.state` is not drawn (`tests/computer-use/register.test.ts`: `a question left in the state by a reload, with no call waiting on it, is not drawn`). The other modules, all in `hooks/computer-use/`: `bridge.ts`: call/approval rounds; `question.ts`: queued question with injected clock/wait/band; `routing.ts`: bridge name, own-tool test, lease and approval limit; `presentation.ts`: pure reply, command, bridge and approval-band text; `prompts.ts`: prompt, tool schema and `denyOwn`, the model guidance that steers to the bridge (kept beside `PROMPT`, not in `presentation.ts`); `helper.ts`: socket link, with `postStarting` (start-on-demand, injected probe); `commands.ts`: the `/codex-cu` table; `model.ts`: wire types.
- `toAnswer` turns Codex's MCP blocks into Messages API ones: an image (`data`, `mimeType`) becomes `{ type: 'image', source: { type: 'base64', media_type, data } }`, since the API rejects one without `source`; an image without data and other block kinds are dropped (`tests/computer-use/presentation.test.ts`: `toAnswer turns a Codex MCP image into a Messages API image block, after the notes`).
- `/codex-cu` commands: `commands.ts` `COMMANDS` is the only list; parse, `HELP` and the registered description come from its rows, whose help lines and synopses are `COMMAND_TEXT` in `presentation.ts`. A new subcommand is one row, its `COMMAND_TEXT` entry and a handler in `register.tsx` (the `Handlers` type fails until it exists). Pinned by `tests/computer-use/command-table.test.ts` and `tests/computer-use/command-rows.test.ts`.
- `postStarting` starts the helper through launchd once and polls twenty times with `sleep 0.25` through `process.run` (waiting in `$.clock.sleep` would spend the hook's time); a start that fails returns the first reply and a rejecting probe rejects (`tests/computer-use/helper.test.ts`). `session.end` does not use it: one `post` release, no kickstart or retry (the hook's budget is shared and 1.5 s), any failure swallowed (`tests/computer-use/session-end.test.ts`). The own-desktop-tool guard has a `.catch` (`holdOwnDesktop`) that re-checks `isOwnDesktopTool`, so a failed hook still refuses Claude's own desktop tools; on a re-entry (`next.error.kind === 're-entry'`), or when the switch was never read, it refuses with the neutral `UNCHECKED_OWN` text instead of "Codex computer use is on" (`tests/computer-use/session-end.test.ts`).
- `helper/helper.mjs`: Unix-socket entry point, one `ROUTE_TABLE` entry per route (`helper/test/routes.test.mjs` pins the check order and every status and body); `helper/lib/hub.mjs`: sessions/ownership/approvals, with what each approval decision does (slot, claim, stop, answer) in one `DECISION_EFFECTS` row; a decision with no row fails closed (declined, nothing claimed). Ending a session (reset, release, eviction, close) marks it ended: a call still queued on it is refused with an error, starts no client and claims no app, and `reset` frees the caller's apps again once its session is gone. `status` reports only apps whose lease is live, per owner and per caller. `forget` without an `app` names the missing field. `helper/test/hub-effects.test.mjs` pins every row, unlisted decisions, teardown order, the queued-call races and `status`; `approvals.mjs`: policy (`decide`); `codex-approvals.mjs`: saved list; `apps.mjs`: app names and bundle ids; `owners.mjs`: per-app holder; `mcp-client.mjs`: stdio MCP client; `version.mjs`: helper version; `config.mjs` and `helper/launch.mjs`: connection.
- `helper.mjs` starts listening only when its real path is `process.argv[1]`'s real path (`isMain`, so a start through a symlink works); otherwise it logs `not started` and does not listen (`helper/test/main-guard.test.mjs`, on an isolated copy).
- Helper is Node ESM, run by the ChatGPT app's `node`; `helper/install.sh` installs LaunchAgent `com.anderson-spider.codex-cu` in `~/.claude/mcp/codex-cu`.
- Socket `run/helper.sock` and approvals `state/approvals.json` are fixed beside installed `helper.mjs`. Neither installer nor uninstaller edits Claude settings; uninstall retains code/approvals/logs. Install accepts only `--check` or no arguments; uninstall takes none (`helper/test/config.test.mjs`).
- Shared contract: routes, choices, reply key sets (`replies`, including the `app` inside each held reply: what the helper always or sometimes sends, and what hooks reads, measured in `tests/computer-use/contract.test.ts`; a trim of an unread field needs that evidence first), lease and LaunchAgent label are written once per side and pinned by `helper/test/contract.mjs`, which both test halves compare (`tests/computer-use/contract.test.ts`, `helper/test/contract.test.mjs`); hooks never import helper modules at runtime. Update together: `contract.mjs`; `hooks/computer-use/model.ts` (`ROUTES`, `CHOICES`, `RouteReplies`, the only reply-shape source), `routing.ts` (`LEASE_MINUTES`), `helper.ts` (`LABEL`); `helper.mjs` (`ROUTES` and its `ROUTE_TABLE` entry), `lib/approvals.mjs` (`CHOICES`), `lib/hub.mjs` (`LEASE_MS` and the reply keys); `install.sh` and `uninstall.sh` (`LABEL=`). The tool input is typed in `types/index.d.ts`; its keys match `prompts.ts` `INPUT_SCHEMA` at compile time, and the `tool.call` matcher in `computer-use/register.tsx` is the literal tool name (equal to `routing.ts` `TOOL`).
- Bump `helper/lib/version.mjs` when helper behavior changes; users rerun `install.sh` to load it.
- App approvals expire five minutes from **before entering the queue**; clock/poll failure must never approve. Coverage: `tests/computer-use/question.test.ts`; Claude desktop-tool refusal while on: `tests/computer-use/register.test.ts`.

### Helper checks

- The plugin's own checks above cover the hooks; the helper tests run on their own (CI runs them on the system `node`):
- `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node --test plugins/codex/helper/test/*.test.mjs`.
- `helper/test/contract.mjs` is the shared caller, socket, route, choice, lease and label evidence. Host timeout tests inject `clock.now` and release held polls; helper tests use injected fakes or an isolated copied installation, never installed run/state directories.
