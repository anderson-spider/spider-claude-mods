# codex

Setup, use and privacy: read [README.md](README.md).

- `hooks/register.tsx`: the literal `$.tool.register`/`$.command.register` calls in `session.start` (the engine's scan needs the names), the `tool.call` and `command.run` hooks, the `prompt.compose` section, and the host access each run gets (`depsOf`: `$.process.spawn` for the Codex child, `$.process.run` for `sleep`, `mkdir`, `cp` and `sips`, the files, `TMPDIR`, `HOME`, `CODEX_HOME` and `PATH`). Pure modules take that access injected.
- `args.ts`: the `codex exec` argv. Every run is locked read-only and never asks for approval (`-c sandbox_mode="read-only"`, `-c approval_policy="never"`, whatever the user's `config.toml` says; `exec resume` takes no `--sandbox`), an ask searches the web (`web_search="live"`) and an image run does not; a new thread gets `--thread-source` and, for an image, `-C` the plugin's empty folder; `--` ends the options because `--image` takes several values (`tests/args.test.ts`: `a new ask runs read-only, never asks for approval, searches the web and records its source`, `a follow-up resumes its thread, keeps the read-only lock and takes no folder or source`).
- `events.ts`: reads the `--json` lines (`thread.started`, the last `agent_message`, `turn.failed`, `error`); an `error` event before an answer (a reconnect) does not fail a run that answers (`tests/events.test.ts`: `an error event before an answer does not fail a run that answers`).
- `runner.ts`: `launch` (one child, its events, `stop` closes the stream, which kills it), `within` (waits through `sleep` host processes, a minute at most each, since a hook's clock stops only while a host call is in flight) and `createRunner`: the foreground wait (`foregroundMinutes`), then the same child as a background job up to `backgroundMinutes` from its start, stopped past it; a job's end sends a toast and a `prompt.submit` notice with paths and the thread, never the answer (`tests/runner.test.ts`: `past the foreground wait the run goes on as a job, whose end sends a notice without the answer`, `a job past the background limit is stopped and reported as timed out, with its thread`). Runs do not queue: each is its own child. The jobs list lives in memory and is lost on a reload.
- `output.ts`: answers go to `$TMPDIR/codex/` as Markdown with the thread first; images are copied from `$CODEX_HOME/generated_images/<thread id>/`, where Codex saves them (its `--json` stream does not name them): the names there before a follow-up are left out, the rest go out oldest first (`tests/output.test.ts`: `the images a run added are copied out oldest first, numbered when there are several, with previews`).
- `input.ts`: tool input to `Request` (thread id, model and effort shapes that cannot break the TOML value, absolute paths; images among `files` become `--image`, the rest are listed in the prompt for Codex to read). `locate.ts`: `codexPath`, else PATH, else `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`. `doctor.ts`: `/codex-doctor`. `presentation.ts`: every text the model or the person reads; `prompts.ts`: tool descriptions and the system prompt section; `tool-schemas.ts`: input schemas and command texts.
- `hooks/schema.ts`: the shared `SchemaFor` and `allOf`, a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; each `inputSchema` satisfies `SchemaFor` of its `McpToolInputs` entry in `types/index.d.ts`. A new tool: its schema in `tool-schemas.ts`, its `McpToolInputs` entry, its literal registration and `tool.call` hook in `register.tsx`, and the names in `tests/register.test.ts` (`session start registers the ask, image and jobs tools and the three commands`).
- Tests: `tests/fakes.ts` (a scripted Codex child and memory output deps) for the pure modules, `tests/host.ts` (the host fake, including a `process.spawn` generator) for `tests/register.test.ts`.
- Checks: [root commands](../../AGENTS.md#commands). A live check: `/codex-doctor`, then `/codex-ask` and `/codex-image` (the last spends OpenAI usage).
