# secrets

Usage/privacy: [README.md](README.md).
- Code Mode stays available: the hooks module registers no event that turns it off (`tool.call`, `tool.run`, `tool.check`, `tool.judge`, `agent.spawn`, `agent.offer`, `session.send`, and the classic `PreToolUse`, `PostToolUse` and the like inside a module; `session.append` is fine). The tool comes from an MCP server, the fence is a `PreToolUse` command hook in `hooks/hooks.json` beside `modules` (measured: Code Mode starts, and the hook sees and can deny each call the code makes). Keep it that way.
- Three parts, one folder of pure modules between them. Node side (plain JavaScript typed by JSDoc, since `claude plugin validate` type-checks any TypeScript the plugin runs as hooks-module code, without Node; `tsconfig.node.json` checks it with `checkJs`): `server/` is the MCP server `.mcp.json` starts (`main.mjs`: umask 077, the queue named by `process.ppid`; `mcp.mjs`: JSON-RPC over stdio, `initialize`, `ping`, `tools/list`, `tools/call`; `tool.mjs`: `REQUEST_SECRET`, its schema under `@satisfies {SchemaFor<RequestSecretInput>}`; `ask.mjs`: checks the input, writes the request to the session's queue, waits up to `ACK_WAIT_MS` for the module's answer file and returns `askedMessage`, or withdraws a request nobody took and returns `NO_PANE`; `node.mjs`: owner-only folders and files, written whole through a `.partial` rename). `fence/main.mjs` is the hook: reads the hook input on stdin, denies by `fenceReason` (`hooks/guard.ts`) or for a saved value the input carries (`carries`, `hooks/scrub.ts`, over `liveValues`), prints nothing to allow; it fails open (`onFailure: continue`, timeout 10 s) since the scrubber is the guarantee.
- `hooks/register.tsx` (the module): `session.start` finds the Claude Code process (`claudePid`: `echo $PPID`, the same parent the MCP server has), registers `/secrets`, polls the queue every `TAKE_MS` (`take`: each `<id>.json`, oldest first, is read, removed, checked again with `parseQueued`, shown by `show`, which queues it, opens the pane and looks at `$.ui.panes()` a few times over about a second with `isDrawn`, then answered with `<id>.ack` holding `pane` or `band`), and `refresh` (deletes expired files, rebuilds the scrubber's index, removes other sessions' queues untouched for `STALE_MS`; at session start and hourly). Also the card (`card`, drawn by the `Pane` and `AbovePrompt` `ui.render` hooks), `answer` (saves on stdin or declines, then sends the model a `$.prompt.submit` message) and the `session.append` scrubber. `$` goes only to these top-level functions of the file.
- Pure modules, shared by the module and Node, so they import no value from each other (Node needs a file extension the validator refuses; a type import is fine): `hooks/queue.ts` (the queue's paths, file names, ids, `Placement`, the waits), `hooks/store.ts` (folder, file names, the 24 hour expiry, the write script: umask 077, `set -C`, the value on stdin and never in argv), `hooks/guard.ts` (`bashReason`, which also refuses a recursive search from a folder above the secrets folder, as `ancestors` lists them, since some builds have no Grep or Glob tool and search through Bash; `toolReason`; `fenceReason`; `DENY`), `hooks/scrub.ts` (the index, `scrubBlock`, `carries`), `hooks/request.ts` (`NAME`, input checks, `parseQueued`, the queue of cards, every message Claude receives). `hooks/schema.ts`: the shared `SchemaFor` and `allOf`, identical in every plugin that has one, with its type cases in `tests/schema-types.ts`. State contract: `types/index.d.ts` (`secrets.requests`, `secrets.isWaiting`).
- Tests mirror modules. `claude plugin test` runs `tests/*.test.ts`: `tests/store.test.ts`, `tests/guard.test.ts`, `tests/scrub.test.ts`, `tests/request.test.ts`, `tests/register.test.ts` (`a request the server queued opens the pane, and the server is told the card is in the pane`, `only this session's queue is taken: another Claude Code process's request is left for it`, `the value pasted in the card goes to a private file on stdin and Claude is sent its path`, `the scrubber replaces a saved value in any row before it is stored, including after a restart`, `session start removes the queues of sessions untouched for an hour, and keeps its own and fresh ones`); `tests/host.ts` is the host fake (`world`, `started`, `request` and `ack` for the queue, `until` to move the clock) with an in-memory secrets folder. `node --test` runs `tests/node/*.test.mjs`: `server.test.mjs` (`ask` with injected files and clock, the protocol, `node server/main.mjs` listing the tool) and `fence.test.mjs` (`decide` and `node fence/main.mjs` against a temporary home folder, the server's owner-only files).
- The value is on screen in the paste field (the engine's `Input` has no mask) and in the plugin's memory (the scrubber's index) and the fence's (one call's `liveValues`), nowhere else: not in argv, a prompt, a toast, a queue file or a message to Claude. A change that puts it in any of those breaks the plugin's one promise; `tests/register.test.ts` checks argv and the messages. The transcript's `toolUseResult` side field is out of a hook's reach (README, Limits).
- Checks: [root commands](../../AGENTS.md#commands); `pnpm --filter secrets typecheck` runs `tsc` for the module and `tsc -p tsconfig.node.json` for the Node side. A live check: start `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude --plugin-dir plugins/secrets` with the installed copy off, look for `Code Mode (experimental) is on`, ask for a test secret, paste it, then have one piece of code `Read` and `cat` the file (refused) and `echo "$(cat <file>)"` (scrubbed).
