# subagent-effort

Usage/privacy: [README.md](README.md). Each module has a mirror test in `tests/`; `tests/host.ts` is the fake host (`world`, `started`, `call`, `settle`), and fake coverage is not live routing evidence.

## Modules

- `hooks/register.tsx`: every `on(...)` and `$` call. `session.start` registers the `subagent-effort-stats` command; the `tool.call` hook on `Agent` has Jev decide the effort and its `.catch` dispatches the call as it came when routing fails; `turn.complete` ends background runs; `command.run` prints the Jev access of this session and the summary. Host access stays literal here and goes only to top-level functions of this file (`io`, `files`, `observe`, `record`, `accessLine`, `warnOff`, `dispatched`). The hook never rewrites the `Agent` call: auto mode (server review, Claude Code v2.1.271 and later) reviews the call the model wrote and refuses one a hook changed afterwards, and `agent.spawn` takes a model but no effort. A call without Jev's effort is refused instead with `askText`, its input untouched, and Jev's pick waits for it in `asked` (keyed by agent type, description and prompt, so parallel calls with one task wait apart; bounded, dropped on reload), with the `$.clock.now()` time of the first refusal, so the decision line records `sentBack` and `sentBackMs`; after `ASK_AGAIN` refusals the call goes as it came. `tests/register.test.ts` (`Jev picks the effort of any native agent type: a call without it is sent back to come again with it, untouched`, `a call that comes back twice with another effort goes as it came, so a model that will not follow never loops`, `parallel calls with the same task are each sent back for Jev’s effort: each waits apart, by its description`, `a routing failure dispatches the call once as it came and writes no record`).
- `hooks/effort.ts`: the whole policy and the assessment: `QUESTION`, `EFFORTS` (one per criterion, `max` never), `POLICY`, `CALIBRATION` (bumped with any change to those three), `JEV_INPUT_USD_PER_MTOK` and `jevCostOf`, `levelOf`, `distribution`, `TASK_CHARS` (800: the head of the task is rated alone, since ratings followed brief length), `FULL_CHARS` (4000: a longer task is also rated up to that length, in parallel; the decided `level` is the higher of `headLevel` and `fullLevel`, at most `MAX_RAISE` (1) above the head, and a failed second call leaves it to the head), `clipped` (key, then `redact`, then the cut) and `assessEffort` (the head's call starts first, so it takes the slot and the breaker's probe). `tests/effort.test.ts` (`the head is rated alone; a longer task is also rated up to the full length, and the higher level decides, at most one above the head`, `a task that fits the head asks Jev once, and a failed comparison leaves the decision as the head made it`). `tests/effort.test.ts`: `every assessment failure picks no effort, names the reason, and a logging failure changes nothing`.
- `hooks/caps.ts`: the `caps` option (`capsOf`, `DEFAULT_CAPS` when unset, `none` off) and `capped`, which lowers only a pick above the agent type's cap. `register.tsx` parses the option once per load and logs the dropped pairs at `session.start`. `tests/caps.test.ts` (`without the option the read-only built-in agents are capped, none turns caps off, and bad pairs are named`, `a cap lowers only a higher pick and says it applied; a type without a cap keeps Jev's effort`); `tests/register.test.ts` (`an agent type's cap holds Jev's pick down, named in the refusal and recorded beside Jev's own level`, `the caps option replaces the default caps, none turns them off, and a bad entry is logged and dropped`, `a cap never touches a call Jev did not route`).
- `hooks/ledger.ts`: pure line builders (`decisionLine`, `afterAgentCall`, `afterTurn`), `createPending`, `appendLine` (one process-wide queue, rotation at `ROTATE_AT`), `parseLedger`, `ERROR_CLASSES` and `errorClassOf` (the kind of an error the `Agent` call returned, from fixed prefixes of the host's text, which never reaches the ledger), `summarize` (groups by model family and effort and by agent type, only runs of the current calibration; calls that never ran, per error class, and older runs counted apart; the decisions the one-level limit held, `cappedRaise`, and the calls sent back with their median wait), `MIN_RUNS` (a group with fewer runs is left out of the text and counted), `formatSummary` and `usd` (two significant digits, so a Jev cost of a few millionths of a dollar never shows as zero). `tests/ledger.test.ts` (`a decision line projects each field and drops anything that is not a plain word or a count`, `calls that never ran and runs of an older calibration stay out of the groups, and caps that lowered Jev are counted`, `this calibration's decisions compare the head's level with the full brief's; one without both levels is left out`, `an error the Agent call returned is recorded by its class, never by its text, and counted per class when it never ran`, `a group with fewer than three runs is left out of the text and counted, while the summary keeps it`, `a call sent back is counted with its wait until it went; lines that do not record it are left out`); `tests/register.test.ts`: `a decision records how many times its call was sent back and the time from the first refusal until it went`.
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, the key from the sensitive `apiKey` option or, when it is absent or blank, `JEV_API_KEY` (`pickSource`), refused when the project or local settings declare the source in use (`repoDeclares`), whole-text redaction before clipping, deadline, retry, gate and breaker. `key.ts` also owns `OFFS`, `isOff` and the fix text of each reason (`OFF_TEXT`). `tests/key.test.ts` (`any repository env declaration of JEV_API_KEY is refused`, `the apiKey option wins over JEV_API_KEY; an absent, null or blank option falls back to the environment`, `a repository declaration of the apiKey option is refused, and only the declaration of the source in use counts`). `tests/jev.test.ts` (`one retry on 429 and 5xx while the deadline allows it, none on other statuses`, `three failures pause Jev, then one probe goes through and a success closes it`); `tests/redact.test.ts`: `redacts email addresses but not package versions`. `register.tsx` passes `options.apiKey` and reads `$.env.get('JEV_API_KEY')` with a literal name, which the engine's source analysis requires.

## Invariants

- Only the effort is Jev's, and no field of a dispatched call is changed: the model, the description and the rest go as the model wrote them. Jev decides over an effort the call came with (`received` records the first one, across the calls sent back); a fork and an empty task pass untouched; Jev off or failing, and any routing failure, dispatch the call as it came, its own effort included. `tests/register.test.ts` (`Jev decides over an effort the call came with: another one is sent back, its own goes as it came`, `when Jev is off or fails, an effort the call came with goes as it came and is recorded as received and applied`, `a fork or an empty task passes untouched, unrouted and unrecorded`).
- A decision line records the effort the call came with (`received`) and the one applied (`effort`); null is the agent's usual effort. Its Jev fields (`jevMs`, `jevTokens` from the response's `usage`, `jevCostUsd` from `JEV_INPUT_USD_PER_MTOK` in `hooks/effort.ts`) cover the routing call alone, apart from the subagent's duration and tokens on the outcome line. `tests/effort.test.ts`: `the estimated Jev cost charges input tokens only, at the published rate`. `tests/ledger.test.ts`: `the summary groups outcomes by model family and effort, and counts decisions per source and the explicit efforts Jev replaced`.
- The ledger is the plugin's only file (`~/.claude/subagent-effort/routes.jsonl`, one rotated generation). A decision line goes in before dispatch, an outcome line after the host result (with the call's own model when the host reports none, and its background mode when it failed: `runsInBackground` in `hooks/ledger.ts`, the call's `run_in_background` or, for the main conversation in the desktop app or VS Code, always background), none when a hook or the permission check denied the call, which never ran (`tests/ledger.test.ts`: `the Agent result becomes a foreground outcome, a background launch, or nothing for a refusal or an unknown shape`); observation never changes the host result, and its failure is one fixed debug line. `tests/register.test.ts` (`observation survives a failing ledger: the dispatch and its result are unchanged and one debug line names the miss`, `in the desktop app or VS Code, where the main conversation's agents always run in background, an error is a background outcome`); `tests/ledger.test.ts`: `a call runs in background when it asks to, or when the desktop app or VS Code runs the main conversation there`.
- A line never holds the task, a prompt, an answer, a path or the key; the brief appears only as its length. `tests/register.test.ts`: `no line ever holds the task, a prompt, an answer, a path or the key`.
- The stats texts carry no plugin-name prefix: the host adds it. `tests/register.test.ts`: `the stats command checks Jev access the way routing does, summarizes the records and never prints the key`.
