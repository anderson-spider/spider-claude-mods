# orchestrator

Setup, use and privacy: read [README.md](README.md). The model is T3 Code's orchestrator MCP server (`docs/orchestration-v2/orchestrator-mcp-server.md` and `packages/contracts/src/orchestratorMcp.ts` there) and its ACP client policy (`packages/provider-acp/src/server/clientPolicy.ts`); keep names, statuses and the `next` text as T3 Code has them.

- Three processes, so Code Mode stays available: no module hook on tool calls (`tool.call`, `tool.run`, `session.send` and the like turn it off).
  - `server/` (one per session, started from `.mcp.json`): `main.mjs` (options from `SPIDER_ORCHESTRATOR_OPTION_*`, taken out of the environment, a placeholder left as `${user_config.*}` read as unset; every call forwarded with the caller `{ sessionId (CLAUDE_CODE_SESSION_ID), cwd (CLAUDE_PROJECT_DIR), settings }`, a progress beat every 5 s; a result with `error` is `isError`), `mcp.mjs` (JSON-RPC over stdio, antigravity's copy), `daemon-client.mjs` (one socket connection, the daemon started detached with its output in `daemon.log` when nothing answers, a dropped connection opened again once), `tools.ts` (the four tools; inputs typed and each schema checked by `SchemaFor`; T3 Code's `target` is flattened to `providerInstanceId`, `model` and `effort`, since `SchemaFor` types no nested object).
  - `daemon/` (one per user and plugin version: the socket is `daemon-<version>.sock` in the state folder, mode 600 in a 700 folder): `main.mjs` (a socket left by a dead daemon is removed, one that answers makes the new daemon exit; `recover` at start; exit after 15 min with no client and no task; SIGTERM stops the tasks), `orchestrator.mjs` (pure, deps injected: input checks, the runtime mode against the caller's ceiling, `clientRequestId` per parent session, tasks scoped to their parent session, `wait` up to 45 s, a task's end waking its waits or else leaving a notice, `task_status` of an ended task taking the notice back, cancel disposing of it; `recover` ends as `interrupted` a task whose owner daemon is dead and leaves one a live daemon runs; capabilities cached 10 min), `acp.mjs` (one turn: spawn in its own process group, `initialize` with no fs and no terminal, `session/new`, `set_mode default`, `set_model`, `thought_level`, the prompt, permission requests answered by `policy.mjs`, any other client method refused with -32601, re-prompting with `RETRY_PROMPT` while a turn ends empty after a new refusal (agy ends its turn at each one, measured on agy 1.5.10), up to `MAX_RETRIES`; a deadline or an abort sends `session/cancel`, then SIGKILL after 5 s; the group is SIGTERMed and SIGKILLed when the turn ends; `probe` reads models and thinking levels with no prompt), `policy.mjs` (T3 Code's dispositions; a mutation in `auto-accept-edits` passes only with every location inside the work folder by realpath, failing closed), `agy.mjs` (the provider: `agy acp --cli_dir_name=spider-orchestrator --sandbox`, the profile's `settings.json` written before every task, a profile whose `config/hooks.json` or `config/mcp_config.json` sets anything refused, agy located), `store.mjs` (tasks as `tasks/<taskId>.json`, notices as `inbox/<sessionId>/<taskId>.json`, temp file and rename), `socket.mjs`, `jsonrpc.mjs` (a line-based peer; non-JSON stdout lines are skipped).
  - `hooks/register.tsx`: the `prompt.compose` section (`prompt.ts`, after T3 Code's orchestration instructions) and, every 2 s, the session's notices: each file removed with `rm`, then its text submitted with `$.prompt.submit`, oldest first (`inbox.ts`). `paths.ts` is the state folder for both sides: the daemon imports it as TypeScript (Node strips the types).
- Tests: `tests/register.test.ts` (`claude plugin test`: no tool or command registered, notices delivered once, the prompt section). `tests/node/` (`node --test`): `policy.test.mjs`, `acp.test.mjs` and `server.test.mjs` against `fake-agent.mjs` (a scripted ACP agent: `FAKE_AGENT_SCRIPT` and `FAKE_AGENT_LOG`), `orchestrator.test.mjs` with a scripted turn; `server.test.mjs` runs the server, the daemon and the fake agent end to end under a temporary HOME in `/tmp` (a socket path has a length limit a macOS temporary folder can pass).
- Checks: [root commands](../../AGENTS.md#commands); `typecheck` also runs `tsc -p tsconfig.node.json` (server, daemon, tests/node). A live check: `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude --plugin-dir plugins/orchestrator` in a scratch git repository, ask Claude to delegate a small task to agy async and end its turn: the result arrives as a prompt from the plugin. It spends agy quota. Stop the daemon afterwards (`daemon.log` names its pid) so a later session starts the current code.
