# sonarqube

Usage/privacy: [README.md](README.md).
- `hooks/register.tsx`: each tool's literal `session.start` registration (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`: tsc fails when the schema's properties, `required`, `type`/`items` differ from `types/index.d.ts` or a literal union's `enum` is not `allOf` of exactly its members; descriptions are unchecked) and `tool.call` hook (with a `.catch` that answers an error), all sharing the top-level `run($, tool, input, options)`: access, then the tool, whose `InputError` or `SonarError` is its answer; answers past 60,000 characters are cut. `accessIo` spells each `$.env.get` name as a literal, so `claude plugin validate` lists them. `hooks/schema.ts`: the shared `SchemaFor` and `allOf`, a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`.
- `hooks/access.ts`: pure url and token resolution over injected settings and environment reads. Sources in order: the `url` and `token` options, `SONARQUBE_URL`/`SONARQUBE_TOKEN`, `SONAR_URL`/`SONAR_TOKEN`; a source counts only whole, and one option alone is refused (`half-option`), never completed from the environment. The source in use is refused when project/local settings give it a value the user source does not (`pluginConfigs` for the options, `env` for the variables), or the settings cannot be read. Messages name the options and variables, never a value (`tests/access.test.ts` (`the url and token options come first, then SONARQUBE_URL/SONARQUBE_TOKEN, then SONAR_URL/SONAR_TOKEN`, `a source counts only whole: a url never gets the token of another source`, `options the repository settings chose refuse the call, unless the user settings give the same value`, `environment variables the repository settings set refuse the call, unless the user settings set the same value`)).
- `hooks/api.ts`: pure `sonar(fetch, base, token)`, injected fetch; GETs to the fixed `ENDPOINTS` only, the query from `URLSearchParams`, the token only in `Authorization: Basic` (`token:`), errors as `SonarError` (`tests/api.test.ts` (`the token goes only in the Authorization header, as Basic token-colon`, `errors become SonarError: refused token, not found with the API message, other statuses, no JSON, no answer`)).
- `hooks/project.ts`: `findProjectKey`, `sonar.projectKey` of the nearest `sonar-project.properties` from the session's folder up to the folder holding `.git` (only the session's folder outside a working tree; `$.session.root()` is where the session started, not the repository's root) (`tests/project.test.ts` (`foldersUp walks up to the folder holding .git, nearest first, and keeps only the start outside a working tree`, `propertyKey follows Java properties: the last value wins, escapes are decoded, a backslash continues the line`)). `hooks/input.ts`: `Ctx` (`sonar`, `detect`), `InputError` and the input checks; `scope` refuses `branch` with `pullRequest`.
- Tools, one module per area: `hooks/quality.ts` (`sonarqube_quality_gate`, `sonarqube_measures`), `hooks/issues.ts` (`sonarqube_issues`, `sonarqube_issue`, `sonarqube_rule`), `hooks/hotspots.ts`, `hooks/branches.ts`. All read only; there is no generic API tool, and `tests/register.test.ts` (`session start registers the seven read-only tools and no other`) pins the set. An issue of a branch or pull request is found by key only with its project in `componentKeys`, so `sonarqube_issue` sends it whenever a scope is given (`tests/issues.test.ts`: `issue of a pull request or branch sends its project, the given or the detected one`). Pull requests need a commercial edition: `sonarqube_branches` answers their error beside the branches (`tests/branches.test.ts`).
- Tests mirror modules; `tests/fake-api.ts` is the fake SonarQube for tool tests (`fakeCtx`) and `tests/host.ts` the host fake (`world`, `started`).
- Live check (not in CI): with `SONAR_URL`/`SONAR_TOKEN` exported, `claude --plugin-dir plugins/sonarqube --allowedTools 'mcp__sonarqube__*' -p '<ask for each tool>'` (`--allowedTools` takes several values, so the prompt goes after `-p`).
- Checks: [root commands](../../AGENTS.md#commands); type-check with `npm run typecheck -- sonarqube`.
